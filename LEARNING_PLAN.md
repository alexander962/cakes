# Дорожная карта обучения — «У Катюни»

## Принятые архитектурные ориентиры

### Локализация

- Две локали: `ru` и `en`; URL — источник истины (`/ru/...`, `/en/...`).
- Последний ручной выбор сохраняется в cookie; при первом посещении учитывается `Accept-Language`, затем применяется согласованный fallback.
- Интерфейсные переводы хранятся в репозитории, предположительно в `shared/i18n`.
- Контент Sanity локализуется на уровне полей одного документа; общие изображения, цены и другие нелокализуемые значения не дублируются.
- До установки сравниваем `next-intl` и самостоятельную реализацию. Предварительный выбор — `next-intl` благодаря поддержке App Router, Server Components, навигации и форматирования.

### Темизация

- Поддерживаем светлую, тёмную и системную темы.
- Семантические CSS-переменные задаются глобально, SCSS Modules используют их через `var(...)`.
- Ручной выбор хранится в `localStorage`; при его отсутствии используется `prefers-color-scheme`.
- Активная тема отражается через `data-theme` на `<html>`.
- До установки сравниваем `next-themes` и самостоятельную реализацию. Предварительный выбор — `next-themes` благодаря работе с системной темой, хранением выбора и предотвращением мерцания.

### FSD и Next.js

Структуру вводим только по мере появления содержательного кода:

```text
src/
  app/        — маршруты Next.js и интеграция приложения
  views/      — композиция конкретных экранов
  widgets/    — крупные самостоятельные блоки
  features/   — пользовательские действия
  entities/   — бизнес-сущности
  shared/     — общий UI, конфигурация и инфраструктура
```

`src/views` заменяет концептуальный слой FSD Pages и исключает конфликт с зарезервированной директорией Next.js `src/pages`. Направление импортов:

```text
app → views → widgets → features → entities → shared
```

Простая страница может оставаться в `app`, пока отдельная композиция в `views` действительно не нужна.

## Этапы обучения

### 1. Основа проекта

- Next.js с App Router, React и строгий TypeScript.
- ESLint и npm-команды.
- Development- и production-сборка.
- Git и удалённый репозиторий.

### 2. Основы App Router

- `layout.tsx`, `page.tsx`, статические и динамические сегменты.
- Параметры маршрута и вложенность layouts.
- Server Components по умолчанию.
- Client Components, `'use client'` и границы серверного/клиентского кода.

Основные страницы пока не создаём: сначала закладываем локализацию.

### 3. Выбор стратегии локализации

До установки сравниваем `next-intl` и собственную реализацию: инфраструктурный код, маршрутизацию, Server/Client Components, типизацию сообщений, fallback, форматирование, тестируемость и влияние на bundle. После сравнения фиксируем решение.

### 4. Основа локализованной маршрутизации

- Локали `ru` и `en`, сегмент `app/[locale]` и проверка допустимых значений.
- Локализованная навигация и редирект с URL без локали.
- Определение языка по cookie и `Accept-Language`, сохранение ручного выбора.
- Корректный `<html lang>`.
- Сохранение пути и search params при смене языка.
- Согласованная работа Server и Client Components и fallback.

### 5. Архитектура FSD без `src/pages`

- Назначение `app`, `views`, `widgets`, `features`, `entities`, `shared`.
- Правила импортов, public API, бизнес-сущности и пользовательские функции.
- Тонкие route-компоненты в `app`; `views` появляется только для содержательной композиции.

### 6. Выбор стратегии темизации

До установки сравниваем `next-themes` и собственный подход: `prefers-color-scheme`, хранение выбора, атрибут `<html>`, раннее выполнение, мерцание, hydration mismatch, синхронизацию вкладок и Server/Client-границу.

### 7. Цветовая система и темизация

- Светлая и тёмная схемы, семантические токены.
- CSS-переменные совместно с SCSS Modules.
- Системная тема, ручное переключение и сохранение.
- Предотвращение мерцания и ошибок гидратации.
- `color-scheme`, контрастность, фокус и доступность.

### 8. Шапка и переключатели

- Навигация, переключатели `RU / EN` и светлой/тёмной темы.
- Сохранение маршрута и параметров при смене языка.
- Клавиатурное управление, доступные названия и активные состояния.
- Минимальная клиентская граница: интерактивность не превращает всю шапку в Client Component.

### 9. Первые UI-компоненты, SCSS и Storybook

- Семантическая разметка, SCSS Modules, адаптивность по Figma.
- `next/image`, шрифты и переиспользуемый UI.
- Storybook сразу после появления первых компонентов.
- Проверка компонентов на русском/английском языках и в светлой/тёмной темах.

### 10. Каталог на временных данных

- `Cake`, `Category`, `Filling`; различия `entities`, `features`, `widgets`.
- Карточка, список, локальное состояние и локализованные данные.
- Истории компонентов во всех нужных контекстах.
- Jest и React Testing Library при появлении проверяемого поведения.

### 11. Sanity CMS

- Studio, schemas, GROQ, изображения, drafts и опубликованные документы.
- Серверный клиент без секретного токена в браузере.
- Кэширование и обновление контента.
- Локализованные поля и slug, выбор текущей локали и fallback.
- Проверка полноты переводов и unit-тесты преобразований.

Хранилище пользователей, заявок и избранного обсуждаем отдельно.

### 12. TanStack Query вместе с Server Components

Каталог не переводим на исключительно клиентскую загрузку:

```text
Server Component
  → initial server fetch или prefetchQuery
  → QueryClient
  → dehydrate
  → HydrationBoundary
  → Client Component использует наполненный кэш
```

- Query keys с локалью, loading, error, retry и отмена.
- Кэширование, invalidation и разделение кэша локалей.
- MSW для API в тестах и Storybook по мере необходимости.

### 13. URL-состояние каталога

- Поиск, фильтры, сортировка и пагинация/infinite scroll.
- URL search params вместе с локализованным маршрутом.
- Серверная обработка URL и клиентские переходы без потери кэша.
- Локализованное форматирование цен и чисел.
- Integration-тесты через React Testing Library и MSW.

### 14. Детальная страница торта

- Динамический локализованный маршрут и локализованные slug.
- Серверная загрузка, prefetch, `loading`, `error`, `not-found`.
- Локализованные metadata, canonical URL и языковые альтернативы.
- Форматирование цены, веса, чисел и дат.

### 15. Формы

- React Hook Form и Zod для заявки, регистрации, входа и восстановления пароля.
- Клиентская/серверная валидация, локализованные ошибки и доступность.
- Проверка поведения через React Testing Library.

### 16. Авторизация и хранение данных

Сначала выбираем хранилище пользователей, стратегию сессий и место хранения заявок/избранного. Затем подключаем Auth.js: базовая авторизация, сессия, защита кабинета и серверных действий, сохранение локали при входе; OAuth — позднее.

### 17. Redux Toolkit и RTK Query

- Redux Toolkit только для обоснованного глобального состояния.
- RTK Query для избранного и заявок: queries, mutations, tags, invalidation, optimistic update.
- MSW и локализованные статусы.
- Сравнение с TanStack Query; один ресурс не обслуживается двумя библиотеками.

### 18. Playwright для завершённых сценариев

- Язык и тема, каталог и фильтры, страница торта.
- Регистрация/вход, избранное, заявка и её статус.
- Основные сценарии в основной конфигурации; отдельные проверки комбинаций локали и темы.

### 19. Автоматизация качества

- Prettier, Husky, lint-staged и GitHub Actions.
- Lint, typecheck, unit/integration tests, production build.
- Playwright после стабилизации E2E.
- Проверка отсутствующих переводов, если её поддерживает выбранный инструмент.

### 20. Эксплуатация

- Sentry и локализованный контекст ошибок.
- Docker при появлении конкретного сценария.
- Production-сборка, переменные окружения и проверка темы без мерцания.

### 21. Обновление статусов заявки

- HTTP, polling и WebSocket.
- Жизненный цикл, авторизация, ошибки и переподключение.
- Ограничения serverless и обсуждение отдельного сервиса до реализации.
- Локализованное отображение полученного статуса.

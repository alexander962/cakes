3. Архитектура FSD без src/pages
   Будем использовать такую основу:
   src/
   app/        — маршруты Next.js и сборка приложения
   views/      — композиция конкретных страниц
   widgets/    — крупные самостоятельные блоки
   features/   — действия пользователя
   entities/   — бизнес-сущности
   shared/     — общий инфраструктурный и UI-код
   src/views будет нашим безопасным названием для концептуального FSD-слоя Pages. Это позволит:
- не пересекаться с зарезервированной директорией Next.js src/pages;
- явно отделить маршруты от композиции интерфейса;
- сохранить понятную иерархию FSD.
  Файлы src/app/**/page.tsx должны оставаться тонкими: получать маршрутные параметры, выполнять серверную интеграцию и подключать соответствующий модуль из views.
  Направление импортов:
  app → views → widgets → features → entities → shared
  Не каждый экран обязан сразу получать модуль в views. Простую страницу можно оставить в app, пока отдельная композиция действительно не понадобится.

7. TanStack Query вместе с Server Components
   Каталог не будет переведён на исключительно клиентскую загрузку.
   Разберём последовательность:
   Server Component
   → initial server fetch или prefetchQuery
   → QueryClient
   → dehydrate
   → HydrationBoundary
   → Client Component использует уже наполненный кэш
   На этом этапе изучим:
- initial server fetch;
- QueryClient;
- prefetchQuery;
- dehydrate;
- HydrationBoundary;
- query keys;
- повторное использование серверных данных на клиенте;
- loading, error, retry и отмену запросов;
- кэширование и invalidation.
  MSW подключим здесь, когда появится необходимость стабильно имитировать ответы каталога в тестах и Storybook.

11. Авторизация и хранение данных
    Перед реализацией отдельно выберем:
- хранилище пользователей;
- стратегию сессий;
- место хранения заявок и избранного.
  После решения подключим Auth.js:
- базовая авторизация;
- управление сессией;
- защита личного кабинета;
- защита серверных действий;
- OAuth только после базового варианта.
12. Redux Toolkit и RTK Query
- Redux Toolkit для обоснованного глобального клиентского состояния.
- RTK Query для избранного и заявок.
- Queries и mutations.
- Tags и invalidation.
- Optimistic update.
- Тестирование API-сценариев с MSW.
  TanStack Query и RTK Query не будут обслуживать один ресурс. После реализации сравним их подходы.
13. Завершённые пользовательские сценарии и Playwright

- открытие каталога;
- поиск и фильтрация;
- переход на страницу торта;
- регистрация и вход;
- добавление в избранное;
- отправка заявки;
- просмотр её статуса.
